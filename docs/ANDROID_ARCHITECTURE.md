# Aether Android Architecture & Technical Roadmap

## 1. Executive Summary

Aether Desktop is an advanced Windows network routing and VPN control utility built with **Tauri v2** (React + TypeScript + Vite + Tailwind CSS) and a **Rust** backend coordinating **Aether** (WireGuard/MASQUE proxy engine) and **sing-box** (tun interface, traffic classification, and secondary proxy routing).

Tauri v2 natively supports Android as a first-class mobile compilation target. This document outlines the complete architectural design, operating system adaptation layer, and implementation blueprint for porting Aether to **Android (API 26+ / Android 8.0 through Android 15+)**.

---

## 2. Core Architectural Contrast: Windows vs. Android

On Windows, network isolation, TUN creation, and process execution rely on OS-level administrator privileges and standalone executable processes. Android enforces a strictly sandboxed, SELinux-isolated, non-root mobile security model.

| Dimension | Windows Desktop Architecture | Android Mobile Architecture |
| :--- | :--- | :--- |
| **TUN Interface** | Wintun kernel driver (`wintun.dll`) installed by elevated child process | Android OS virtual TUN created via `android.net.VpnService.Builder.establish()` |
| **Privilege Model** | Requires Administrator Token elevation (UAC prompt) | Standard user application. System shows one-time Android VPN authorization dialog |
| **Execution Model** | Standalone child processes (`aether.exe`, `sing-box.exe`) spawned via `std::process::Command` | **In-process native execution**. Standalone daemons are prohibited by Android W^X & background execution limits |
| **Process Lifecycle** | Controlled by Windows Job Objects and desktop process supervisor | Managed by Android **Foreground Service** (`VpnService`) with persistent status bar notification |
| **Routing Loop Prevention** | Process name matching (`process_name: ["aether.exe", "sing-box.exe", "xray.exe"] -> direct`) | Socket protection via `VpnService.protect(socketFd)` system call (marks socket with `SO_MARK` or binds to physical Wi-Fi/Cellular interface) |
| **Application Routing** | Windows binary names (`discord.exe`, `spotify.exe`, `steam.exe`) | Android Package Names (`com.discord`, `com.spotify.music`, `com.valvesoftware.android.steam.community`) |
| **DNS Hijacking** | Sing-box TUN Hijack DNS (`172.19.0.2:53`) with native route metric priority | Virtual TUN DNS specified in `VpnService.Builder.addDnsServer("172.19.0.2")` |

## 3. Recommended Technical Stack & Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                 React + Tailwind Mobile UI                  │
│       (Existing web frontend running in Android WebView)    │
└──────────────────────────────┬──────────────────────────────┘
                               │ Tauri v2 IPC Channel
┌──────────────────────────────▼──────────────────────────────┐
│                    Tauri Android Plugin                     │
│                 (Kotlin: AetherVpnPlugin)                   │
└──────────────┬───────────────────────────────┬──────────────┘
               │ Method Call                   │ JNI
┌──────────────▼──────────────┐ ┌──────────────▼──────────────┐
│      AetherVpnService       │ │      Rust Mobile Core       │
│ (android.net.VpnService)    │ │   (aarch64-linux-android)   │
│  - TUN Builder              │ │  - Configuration generator  │
│  - Foreground Notification  │ │  - Latency / ping testing   │
│  - Socket Protection        │ │  - Subscription manager     │
└──────────────┬──────────────┘ └──────────────┬──────────────┘
               │ File Descriptor (`fd`)        │ Settings / Rules
┌──────────────▼───────────────────────────────▼──────────────┐
│                Sing-Box Mobile Core (libbox)                │
│    (Go Mobile C-Archive compiled for arm64-v8a / x86_64)    │
│  - Reads/Writes directly from VpnService TUN fd             │
│  - In-process gVisor TUN stack                              │
│  - VLESS / Reality / Shadowsocks / Trojan / WireGuard       │
│  - Per-package Android routing rules                        │
│  - Command server for real-time telemetry & latency         │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 Why `libbox` (Go Mobile) for the Android TUN Engine?

1. **Battle-Tested Reliability**: `libbox` is the official mobile SDK maintained by the sing-box core team, currently powering the official sing-box Android client, NekoBox, Karing, and Clash Meta Android.
2. **Native `VpnService` Integration**: Accepts the Android `ParcelFileDescriptor` directly, seamlessly managing the user-space TUN loop (gVisor or mixed mode).
3. **Automatic Socket Protection**: Hooks directly into `VpnService.protect()`, ensuring zero proxy loops without needing process names.
4. **100% Config Parity**: The JSON configuration format generated by our desktop `SingBoxConfigGenerator` maps directly to `libbox`'s configuration schema with minor mobile adjustments (e.g., swapping `process_name` for `package_name`).

## 4. Android Component Details

### 4.1 `AetherVpnService` (`android.net.VpnService`)

`AetherVpnService` runs as an Android Foreground Service to prevent the system from killing the connection during deep sleep / Doze mode.

**Key Responsibilities**:
- **Establish TUN**:
  ```kotlin
  val builder = Builder()
      .setSession("Aether")
      .setMtu(1500)
      .addAddress("172.19.0.1", 30)
      .addDnsServer("172.19.0.2")
      .addRoute("0.0.0.0", 0)
      .setBlocking(false)

  // Per-app split tunneling if configured
  for (pkg in excludedApps) {
      builder.addDisallowedApplication(pkg)
  }
  for (pkg in includedApps) {
      builder.addAllowedApplication(pkg)
  }

  val tunFd = builder.establish()
  ```
- **Socket Protection**:
  ```kotlin
  override fun protect(socket: Int): Boolean {
      return super.protect(socket)
  }
  ```
- **Foreground Notification**:
  Displays an ongoing notification with current state (`Connected`), active upstream server, download/upload throughput, and a quick "Disconnect" action.
- **Quick Settings Tile**:
  `AetherTileService` enables one-tap connection directly from the Android quick settings panel.

### 4.2 Tauri Kotlin Plugin (`AetherVpnPlugin`)

Exposes high-level commands to the React frontend:

- `prepareVpn()`: Triggers `VpnService.prepare(context)` to launch the OS permission prompt if not yet granted.
- `startVpn(configJson: String)`: Boots `AetherVpnService` with the generated configuration.
- `stopVpn()`: Shuts down the active tunnel and releases the TUN descriptor.
- `getInstalledApps()`: Queries `PackageManager` for installed launchable apps (returning app name, package name, and base64 icon) for the Per-App routing configuration screen.
- `getVpnState()`: Returns current connection status, uptime, and throughput counters.

### 4.3 Adapting Routing Rules to Mobile (`package_name`)

On Windows:
```json
{
  "type": "field",
  "process_name": ["discord.exe"],
  "outbound": "aether"
}
```

On Android, rules specify package names:
```json
{
  "type": "field",
  "package_name": ["com.discord"],
  "outbound": "aether"
}
```

Pre-configured presets for popular Android applications:
- **Discord**: `com.discord`
- **Spotify**: `com.spotify.music`
- **Telegram**: `org.telegram.messenger`, `org.telegram.plus`
- **YouTube**: `com.google.android.youtube`
- **Steam**: `com.valvesoftware.android.steam.community`

## 5. Implementation Roadmap

### Phase 1: Project Scaffolding & Mobile Target Init
1. Install Android SDK, NDK (`r26+`), and CMake.
2. Initialize Android target in the Aether repository:
   ```bash
   npm run tauri android init
   ```
   This generates `src-tauri/gen/android/` containing the Gradle project structure.
3. Add Rust compilation targets:
   ```bash
   rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
   ```

### Phase 2: Kotlin `VpnService` & `libbox` Integration
1. Add `io.nekohasekai:libbox` dependency in `gen/android/app/build.gradle.kts`.
2. Implement `AetherVpnService.kt` inheriting `android.net.VpnService` with libbox `PlatformInterface`.
3. Implement `AetherTileService.kt` for Android Quick Settings.
4. Wire Tauri Kotlin plugin `AetherVpnPlugin.kt` to expose IPC invocations to TypeScript.

### Phase 3: Rust Multi-Platform Refactor
1. Use conditional compilation in `src-tauri/src/process/orchestrator.rs`:
   - `#[cfg(target_os = "windows")]`: desktop process spawning with Wintun.
   - `#[cfg(target_os = "android")]`: delegates directly to the Android VpnService via Tauri mobile plugin.
2. Adapt `SingBoxConfigGenerator` to produce `package_name` rules when compiling for Android.

### Phase 4: UI/UX Mobile Optimization
1. Ensure the React frontend layout is fully responsive down to mobile viewports (360px width).
2. Add safe area insets padding for notch/navigation bar:
   ```css
   padding-top: env(safe-area-inset-top);
   padding-bottom: env(safe-area-inset-bottom);
   ```
3. Implement a mobile "Per-App Routing" screen with a searchable package list and app icons.

### Phase 5: CI/CD & Automated APK Builds
1. Create `.github/workflows/android-release.yml` with:
   - JDK 17 & Android SDK setup.
   - Rust toolchain with Android NDK cross-compilers (`cargo-ndk`).
   - `npm run tauri android build -- --apk`
   - Release artifact publishing for `app-arm64-v8a-release.apk` and `app-universal-release.apk`.

## 6. Security & Battery Optimization Guidelines

1. **Battery Doze Handling**: Request `android.settings.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` during first run to ensure background VPN persistence.
2. **Kill Switch Support**: Support `VpnService.Builder.setBlocking(true)` to enforce strict leak prevention when connection drops.
3. **Zero-Trace Credential Storage**: Secure sensitive subscription URLs and proxy keys in the Android Keystore / EncryptedSharedPreferences rather than plaintext storage.
